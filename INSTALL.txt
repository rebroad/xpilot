Following are the installation instructions for the
UNIX version of XPilot.  For the Windows version
see INSTALL_NT.txt for instructions.

To compile XPilot, you'll need at least:

    A C++ compiler

    X11     (any revision from R4 up to R6 is fine)

    fltk - The Fast Lite Tool Kit.

Also note that XPilot isn't gentle with the X server,
so a fast machine (with a graphics accelerator that
does line drawing in hardware), in a fast network
is the ideal situation.

NEW STYLE INSTALLATION

The doc subdirectory contains an RPM spec file which you can use
to build an XPilot RPM file.  The doc subdirectory also contains
a patch with preferred settings for Local.config under Linux.
!!!!!! Not supported/tested for XPilot++ !!!!!!

OLD STYLE INSTALLATION

The complete installation requires just four steps -- geez, how easy
can it be? :)

================================================================================
1. Install fltk.

       See INSTALL_FLTK.txt for details

================================================================================
2. Edit configuration files:

    A) Run ./config.password
        This sets the server password that will be installed when you do
        `make install`.  Note that an installed password file will not be
        overwritten.

    B) Run ./configure

        Useful options to ./configure ...

        --prefix=DIR
            Default: /usr/local/xpilot
            This is the directory that xpilot++ will get installed to when you
            type "make install".  Maybe you don't have root privileges and
            want to say --prefix="/home/dick/xpilot"

        --enable-chroot=DIR
            ***feature not finished***
            Default: [PREFIX] (/usr/local/xpilot)
            The server programs can run in a chroot jail.

        --enable-vardir=DIR
            ***feature not finished***
            Default: /var/xpilot
            XPilot++ wants a writable directory for the servers to keep their
            output files.  These include:
            - ScoreServer's XML data and configuration
            - Server's "tune" files.  If you use xpilotcontrol to tune the
              options in a running map, then the tuned options are saved in this
              directory.  When a map is loaded, a tune file is looked for.
            If you do not want to use these features, set this value to /dev/null
            If you are running xpilot in a chroot jail, then this directory
            must be below your [PREFIX]

        --enable-debug=yes/no
            Default: no
            Causes the -g option and debugging statements to compiled in.

        --disable-silent=yes/no
            Default: no
            This causes the compiler to echo it's command line.  If you are
            having problems building, then turning this on may help you find
            out what's going wrong.

        --with-mysql[=DIR]
            Default: no
            Enable the building of the MySQL based score engines.  With no
            argument, attempt to use system installed libraries.  Perhaps you
            are like me and need to say something like:
            --with-mysql=/usr/local/mysql-standard-5.0.17-linux-i686-glibc23

================================================================================
3. Compile:

   Just run

        make

================================================================================
4. Install:

   To install the executables, maps, and textures, run

        make install

   and to install the manual pages, run

        make install.man


================================================================================
5. Play:

    Start xpilot5

    You must pick a server first.  Either start a server locally by clicking
    on the Local Server button, or connect to a server on your lan or connect
    to a server on the Internet.

If everything fails, see the FAQ, which you can find in the doc subdirectory.
